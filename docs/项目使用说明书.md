# Flip Vault 项目使用说明书

## 1. 项目简介与功能范围

Flip Vault 是基于 Solana Devnet 与 MagicBlock Ephemeral Rollup（ER）构建的 10×10 翻箱子实时对战游戏，结合了链上资金托管与高频无 gas 交互体验。

### 核心功能
- **10×10 翻箱对抗**：每局包含 100 个红/绿双色箱子，链上记录每个箱子当前状态。
- **阵营分配与守护**：玩家报名后，由链上伪随机/种子算法平均分配至红方或绿方作为守护方。
- **保证金与翻箱计费**：
  - 玩家加入游戏需质押 **30 GAME** 保证金入池。
  - 玩家在报名时预充值点击额度（默认 100 GAME），每次翻箱扣除 1 GAME 计入本局奖池。
  - 游戏期间允许反复翻转任意箱子，所有翻箱花费均累积至奖池。
- **GAME Token 储备池兑换**：
  - 固定测试兑换率：`1 GAME = 0.001 Devnet SOL`。
  - 买入（Buy）：向金库转入 SOL，系统 Mint 相应 GAME Token 至玩家账户。
  - 赎回（Redeem）：销毁玩家 GAME Token，金库按比例退还 SOL（受金库当前 SOL 余额储备约束）。
- **游戏时间与结算规则**：
  - 创建者新建游戏时设置链上开始时间；创建成功至该时间为报名期。
  - 游戏期（Play Phase）：5 分钟（300 秒）。
  - 人数范围：每局 2～100 人。
  - 胜负判定：游戏期结束后，箱子数量占优的一方获胜，获胜阵营玩家按人头平分总奖池；平局时（50:50），所有玩家按各自实际入池代币比例原路退款；玩家未使用的翻箱额度在结算时全额返还。
- **MagicBlock Ephemeral Rollup (ER)**：
  - 支持将 Game 状态账户和 Player 账户一键委托（Delegate）至 MagicBlock ER 节点。
  - 在 ER 层实现亚秒级、免签名/免 gas 的翻箱交互。
  - 游戏结算后通过 `commit_and_undelegate` 将最终状态提交回 Solana Devnet 主链。
  - 委托后 Base Layer 上的账户 owner 会暂时显示为 Delegation Program，这是正常状态；dApp 会通过 Router 的 `getDelegationStatus` 获取该账户实际所在的 ER `fqdn`，并从 ER 读取 Game/Player 最新状态。

## 7. 全部合约指令与操作指南

### 7.1 界面 6 步标准操作流程

dApp 界面顶部提供 **6 大阶段全流程向导 Stepper**，指引玩家从房间创建到终局领奖的完整生命周期：

1. **第 1 步 · 发起游戏 (Create Game)**：
   - 点击右上角或向导中的 **“发起新游戏 (Step 1)”** 按钮，弹出房间创建面板。
   - 系统会在 Base Layer 检查候选 Game PDA 是否已存在，并自动跳过已创建或已委托到 ER 的编号，避免重复初始化错误 `6003 / 0x1773`。
   - 系统自动扫描链上最大现有编号并使用下一个编号（如 `#1`），无需填写或选择房间编号。
   - 选择一个晚于当前时间的 **游戏开始时间**；该时间同时是报名截止时间。确认 100 格宝箱、300s 对战期与保证金规则后，点击 **“直接新建游戏”** 签署交易完成链上 Game PDA 与金库 ATA 初始化，并自动跳转至该房间。
2. **第 2 步 · 游戏列表 (Game List / Lobby)**：
   - 点击顶部 **“游戏大厅 (游戏列表 & 发起)”** 标签进入大厅。
   - 实时聚合链上所有游戏房间，提供按 **全部 / ⏳ 报名招募中 / ⚔️ 激烈交战中 / 🏆 已分胜负** 状态筛选及房间 ID 检索。
   - 每张房间卡片清晰展示房间 ID、状态徽章、参战人数、奖池、翻转次数与阵营对比；游戏详情另展示预计开始时间、预计结束时间和预计总耗时。
3. **第 3 步 · 加入游戏 (Join Game)**：
   - 进入处于报名招募中（Status 0）的战局，未参战玩家右侧面板展示 **加入战局** 模块。
   - 质押 30 GAME 入场保证金，并自主选择预充翻箱额度（如 50 / 100 / 200 GAME，每次翻箱扣 1 GAME，未用额度终局 100% 原路退还）。
   - 实时校验钱包内 GAME 代币余额；若余额不足可点击 **“充值代币”**，按 `1 GAME = 0.001 Devnet SOL` 快速兑换。
   - 点击 **“支付并加入游戏”** 签署交易，合约通过链上伪随机算法自动分配玩家至红方先锋或绿方先锋。
   - 加入仅在游戏处于 `Status 0`、链上时间早于 `start_at` 且人数少于 100 时开放。到达开始时间后，页面会禁用按钮，链上也会以 `6005 / E_JOIN_CLOSED` 拒绝交易。
  - 同一钱包在同一游戏只能加入一次，因为 Player PDA 唯一且不可重复初始化。加入交易原子执行：创建 Player PDA、从玩家 GAME ATA 转入 `30 GAME + 预充额度`、分配阵营并更新人数和奖池；任一步失败均不会扣款或留下半成品状态。
  - Game/Player PDA 会额外保留 0.01 Devnet SOL 的委托租金缓冲，避免 ER 克隆阶段因账户仅有最低 rent 而失败；该金额不是 GAME 消耗，也没有现实价值。
4. **第 4 步 · 等待游戏 (Waiting Room)**：
   - 报名成功后，战局进入 **组队集结等待大厅**。
   - 界面实时展示：距离所设开始时间的报名倒计时、参战人数（满 1 人达到开局门槛，上限 100 人）、红绿双方阵营集结人数看板。
   - 玩家专属信息卡片：展示所分配的红/绿阵营徽章、加入顺位、已质押保证金与可用翻箱额度。
   - 支持一键 **“委托玩家状态到 MagicBlock ER”** 与 **“房主委托游戏全局状态到 ER”**，提前为亚秒级免 gas 翻转对战做好准备。
   - 委托完成后游戏不会消失：详情页会自动切换到 Router 返回的 ER 节点读取；大厅会记录已发现的游戏 ID，并将 Base Layer 房间与 ER 房间合并展示。
   - 当参战人数达到 1 人后，**“开启 5 分钟翻箱大战 (Step 5)”** 按钮高亮激活；若没有其他玩家加入，报名截止后可直接单人开局。
5. **第 5 步 · 开始游戏 (Start Game & Battle Arena)**：
   - 到达所设开始时间后，任意签名者均可点击开始游戏；若提前满 100 人也可立即开局。战局至少需要 1 人，状态切换为游戏中（Status 1）后进入 300 秒（5 分钟）对战倒计时。
   - **动态对抗看板**：红绿实时比分拔河条、红绿箱数实时占比、全场累计奖池金额与翻箱总次数。
   - **战术作战指令**：红方玩家目标将绿色箱子翻转为红色扩大领地；绿方玩家目标将红色箱子翻转为绿色扩大领地；实时显示剩余翻箱点击额度。
   - **10×10 翻箱竞技棋盘**：点击任意箱子即可执行翻转；支持乐观 UI 极速响应，并优先通过 MagicBlock ER 毫秒通道发送。
6. **第 6 步 · 结算游戏 (Settlement & Claim)**：
   - 5 分钟对战时间截止后，点击 **“终盘结算本局比赛 (Step 6)”** 触发结算指令，合约自动对比红绿箱数判定获胜阵营。
   - **终盘战报与荣誉殿堂**：高亮公布最终获胜战队（🔴 红方大捷 / 🟢 绿方大捷 / 🤝 平局和解）、终盘奖池与人均分红计算。
   - **个人结算清单与一键提现**：多人局按获胜阵营平分奖池并返还未使用翻箱额度；单人局无论红绿箱最终占比如何，完整奖池与未使用翻箱额度都结算回唯一玩家。点击 **“领取我的奖金与退款 (Claim)”** 一键提回钱包；已委托状态可点击 **“解除 MagicBlock 委托并回写主链”**。
   - 结算完成后可一键点击 **“发起新游戏”** 或 **“返回大厅”** 开启下一轮对决。

### 7.2 脚本 / 命令行交互示例（Node.js / TypeScript）
```typescript
import { Connection, Keypair, PublicKey, Transaction, sendAndConfirmTransaction } from "@solana/web3.js";
import { buyIxs, createGameIxs, joinIx, flipIx, claimIx, pda } from "./app/src/lib/program";

const connection = new Connection("https://api.devnet.solana.com", "confirmed");
const payer = Keypair.fromSecretKey(/* 钱包私钥 Uint8Array */);

// 创建 1 号游戏，设置 5 分钟后开始（开始时间也是报名截止时间）
const startAt = BigInt(Math.floor(Date.now() / 1000) + 300);
const createTx = new Transaction().add(...createGameIxs(payer.publicKey, 1n, startAt));
await sendAndConfirmTransaction(connection, createTx, [payer]);

// 购买 100 GAME (花费 0.1 SOL)
// buyIxs 会先幂等创建购买者的 GAME ATA，支持新钱包首次购买。
const tx = new Transaction().add(...buyIxs(payer.publicKey, 100n));
const sig = await sendAndConfirmTransaction(connection, tx, [payer]);
console.log("Buy tx:", sig);

// 加入 0 号游戏 (30 GAME 保证金 + 50 GAME 点击额度)
const joinTx = new Transaction().add(joinIx(payer.publicKey, 0n, 50n));
await sendAndConfirmTransaction(connection, joinTx, [payer]);

// 翻转第 15 号箱子 (0-indexed, 0..99)
const flipTx = new Transaction().add(flipIx(payer.publicKey, 0n, 15));
await sendAndConfirmTransaction(connection, flipTx, [payer]);
```

## 9. 常见错误排查与错误码速查

| 错误码 | 标识 | 原因与解决方案 |
|---|---|---|
| `6000` | `E_INVALID_DATA` | 指令字节长度或格式不符合 ABI 要求，检查参数编码。 |
| `6001` | `E_INVALID_ACCOUNT` | 传入账户不匹配（例如 writable/signer 权限缺失或未传正确 PDA）。 |
| `6002` | `E_INVALID_OWNER` | 账户 Owner 不是本程序或对应的 Token Program。 |
| `6003` | `E_ALREADY_INITIALIZED` | Config 或 Game 已完成初始化，不能重复调用。 |
| `6004` | `E_BAD_STATUS` | 游戏状态不满足执行该指令的前提（如游戏未处于 Active 状态即执行翻箱）。 |
| `6005` | `E_JOIN_CLOSED` | 已到游戏开始时间，或尝试在开始时间前提前开局；加入时请换一个仍在招募的房间。满 100 人时报 `6006`。 |
| `6007` | `E_INSUFFICIENT_PLAYERS`| 报名人数未达到最低 1 人要求。 |
| `6010` | `E_OUT_OF_CREDITS` | 玩家预充值的点击额度已耗尽，需追加或等待结算。 |
| `6011` | `E_ALREADY_CLAIMED` | 该玩家已经领取过奖励或退款，不可重复领取。 |
| `6012` | `E_NOT_WINNER` | 玩家所在阵营不是获胜方，且非平局状态。 |
| `6014` | `E_RESERVE` | Treasury SOL 储备不足，暂时无法完全赎回。 |

### 9.1 委托后显示“找不到游戏”

先确认钱包仍连接 Devnet，并点击刷新。委托账户在 Base Layer 由 Delegation Program 持有，不能用“owner 必须等于 Flip Vault Program”作为丢失判断。客户端应向 `https://devnet-router.magicblock.app` 调用 `getDelegationStatus(game_pubkey)`，使用响应中的 `fqdn` 查询 Game；Player 账户同理。Router 返回未委托或暂时没有 `fqdn` 时，等待状态传播后重试，禁止硬编码某个 ER 区域地址。

## 10. 安全注意事项

1. **测试网络边界**：本项目仅部署并运行于 Solana Devnet，所有 GAME Token 及兑换的 SOL 均为测试资产，无现实经济价值。严禁部署到主网（mainnet-beta）。
2. **私钥隔离**：部署与管理 Keypair（`deploy/flip_vault-keypair.json`）仅在本地用于部署授权，绝不提交至代码仓库或在前端暴露。
3. **PDA 与签名校验**：所有敏感状态变更（游戏启动、结算、提款）均强制执行严格的 Signer 校验与 PDA 种子校验，防范伪造账户注入攻击。
4. **溢出安全**：所有代币计费、奖池累加与比例计算均采用 `checked_add`、`checked_mul` 等安全运算函数，发生溢出时立即终止事务。
